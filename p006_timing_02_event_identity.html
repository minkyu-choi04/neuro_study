06B · Verification A · Same event?

원본 event와 P001 event가
정말 같은 컷인가?

두 시간값을 빼기 전에 어느 영화 컷을 뜻하는지 확정해야 합니다. 같은 영화를 보더라도 환자별 pause, skip, replay 때문에 하나의 canonical cut이 나타나는 횟수와 neural onset은 다를 수 있습니다.

비교 대상: original `annotations_patient_aligned.start_time` (NWB에 기록된 subject별 neural onset) 대 우리 P001의 `canonical movie event → cleaned_watchlogs.pts → neural_recording_time` (subject별 neural onset). 두 수치가 모두 신경 기록 시간축이더라도 동일 event 확인 없이 차이를 구하면 무의미합니다.

0. 그림을 보기 전에 알아야 할 용어

이 페이지의 비교 대상은 같은 SUMMER 공개 데이터 릴리스를 이용해 얻은 두 종류의 event onset입니다. NWB(Neurodata Without Borders)는 한 실험 참가자의 spike data, stimulus 정보, 주석표 등을 함께 보관하는 표준 파일 형식입니다. 여기서는 29명의 참가자에 대해 29개 NWB 파일을 사용합니다. P001은 우리가 이 공개 데이터를 이용해 만든 event-window preparation pipeline이며, P006은 P001의 timing을 원본 연구의 timing 경로와 비교하는 별도 audit입니다.

먼저 'annotation'부터 정의

Movie annotation(영화 주석)은 영화의 각 시간 구간에 “Camera Cut이 발생했는가”, “장면이 바뀌었는가”, “인물이 화면에 있는가” 같은 label을 붙이는 작업과 그 결과입니다. 논문에서는 사람이 수작업으로 붙인 label과 자동 처리한 label을 함께 제공하며, 컷은 새 화면이 시작되는 frame에 표시합니다. Camera Cut은 영상의 컷 전환이며, Scene Cut은 연구자의 구조적 장면 구분입니다. 이것을 곧바로 인지적인 기억 경계나 사건 경계라고 부르지는 않습니다.

예를 들어 가상의 영화 120.00초에서 화면 A가 화면 B로 바뀌었다면, 공통 영화 annotation에는 “Camera Cut = 1; start_time = 120.00초”라는 양성 구간이 있을 수 있습니다. 여기서 120초는 환자에게 보여 준 시각이 아니라 영화 자체의 좌표입니다.

용어 / 파일 이름어디에 있으며 무엇을 뜻하나?
annotations_base다운로드한 각 NWB의 stimulus 테이블. 29명의 NWB에 동일한 공통 영화 주석을 담습니다. start_time·stop_time은 영화 presentation timestamp(PTS) 단위 초(seconds), label_name은 label 종류, value=1은 그 구간에서 label이 존재함을 뜻합니다. 연속 프레임에 같은 label이 있으면 하나의 interval로 묶입니다.
aligned_labels.npy원 저자의 NWB 작성 코드가 환자별 작업 디렉터리에서 읽는 intermediate NumPy 파일입니다. 원래 movie annotation을 해당 환자의 재생 이력에 맞춰 만든 결과물로 해석됩니다. 저자의 공개 write_nwb.py는 이 파일을 load하지만, 그 파일을 생성하는 원래 upstream 전체 pipeline을 공개 코드만으로 확인·재현할 수는 없습니다. 그 파일 자체가 공개 NWB 안에 있는 것은 아닙니다.
annotations_patient_aligned다운로드한 각 NWB의 또 다른 stimulus 테이블. 위 intermediate를 이용해 만들어진 그 환자만의 실제 재생을 반영한 annotation intervals입니다. start_time은 해당 환자의 neural recording 시작에 맞춘 onset입니다. 저자 writer의 변환과 P006 reader는 이 수치를 밀리초(ms)로 취급하므로, P006은 1000으로 나누어 초로 변환합니다.
raw_watchlogsNWB에 포함된 원본 재생 로그. 표시된 영화 PTS와 관련 neural-recording clock time의 짝을 담으며, pause/seek가 있었던 재생 이력을 보존하는 데 중요합니다.
cleaned_watchlogsNWB에 포함된 정리된 frame별 재생 로그. 두 열 pts(영화 시간, 초)와 neural_recording_time(신경 기록 시간, ms)가 짝지어져 있습니다. 논문은 pause나 skip을 처리해 모집단 분석을 쉽게 했다고 설명하지만, 원본 raw 로그와 같은 정보량이라는 뜻은 아닙니다.
canonical event우리 연구가 공통 영화 시간에서 유지하는 안정적 event ID. event type과 frame 등으로 정의하고, 그 ID를 각 subject의 playback occurrence(해당 event가 재생된 회차)로 옮겨갑니다. 이는 원 논문 NWB의 field name이 아니라 우리 pipeline에서 만든 분석 개념입니다.

초와 밀리초를 구분하세요. 원본 writer는 aligned-label 원시 시간을 1000으로 나눈 뒤 해당 환자의 raw neural-recording 시작값을 빼고, NWB에 쓰고 있습니다. annotations_base.start_time은 영화 PTS 초, annotations_patient_aligned.start_time은 neural recording 관련 ms이므로 이 둘을 숫자만으로 빼면 안 됩니다. 세부 변환은 original writer: AlignedLabelsData와 NWB 저장 함수에서 확인할 수 있습니다.

1. 하나의 movie cut이 여러 subject에서 다른 시간을 갖는다

Pause가 있어도 event의 movie identity는 같다

2. 두 event-onset 경로는 같은 NWB에서 출발하지만 서로 다르다

원본 path 대 우리 path

Original Figure 7은 annotations_patient_aligned의 positive cut onset을 사용합니다. 우리 P001은 canonical movie time을 cleaned_watchlogs에 다시 매핑합니다. 두 path가 똑같은 mapping algorithm이라고 가정해서는 안 됩니다.

2A. 위 그림을 '코드와 데이터' 관점에서 한 단계씩 읽어보기

원본 연구의 경로: movie annotation → playback alignment → aligned_labels.npy → NWB

Playback alignment(재생 이력 정렬)은 영화 120초의 Camera Cut을 단순히 모든 환자의 신경 기록 120초에 복사하는 것이 아니라, 그 환자가 실제로 언제 그 frame을 봤는지를 반영하는 처리입니다. 환자 A가 영화를 멈추지 않았더라도 기록 시작 시각이 다를 수 있고, 환자 B가 중간에 15초를 멈췄다면 해당 장면의 시각은 더 뒤로 밀릴 수 있습니다. 원 논문은 실제 프레임 표시 시각을 laptop에 기록하고, 약 1초마다 TTL 신호를 neural acquisition 시스템에 보내 두 시스템 시계를 연결했다고 설명합니다. 그리고 각 환자의 raw_watchlog를 이용해 annotation을 재생 이력에 추가 정렬했다고 명시합니다.

따라서 원본 경로에는 적어도 두 개념이 들어 있습니다. 먼저 영화의 frame → 각 환자가 실제로 본 시각을 대응시키는 과정, 그리고 presentation laptop time → neural acquisition time을 TTL 정보로 연결하는 과정입니다. 두 단계는 함께 쓰이지만 동일한 것은 아닙니다.

저자의 write_nwb.py 안에서는 이미 준비된 aligned_labels.npy에서 label 이름(names), presence(values), 시작(starts), 끝(stops)을 읽고 환자별 기록 시작 시각을 반영하여 annotations_patient_aligned라는 NWB table에 넣습니다. 정확히 어느 frame을 앞/뒤 어느 시각에 대응시켰는지에 관한 upstream 생성 로직이 공개된 writer 파일에는 없습니다. 따라서 최종 table을 읽어 쓸 수는 있지만, intermediate를 원본과 비트 단위로 동일하게 재생성할 수 있다고 주장할 수는 없습니다.

예를 들어 entry_index는 source movie event를 식별하는 영구 번호가 아닙니다. writer는 각 label의 aligned intervals를 반복하며 새로 1부터 부여합니다. 그래서 original entry_index=50을 우리 P001의 canonical ID 50이라고 믿고 연결하면 잘못된 match가 될 수 있습니다.

우리 P001의 경로: annotations_base → canonical ID → cleaned_watchlogs → neural onset

우리는 원본의 annotations_patient_aligned.start_time을 그대로 사용하지 않았습니다. 대신 공통 영화 주석에서 Camera/Scene Cut의 양성 구간을 골라 영화 시간과 frame 단위로 안정적 ID를 만든 다음, 각 환자의 cleaned_watchlogs에서 그 frame의 pts를 찾아 동일한 행의 neural_recording_time을 읽습니다. 이때 단위를 ms → sec로 바꿔 해당 subject의 neural event onset을 얻습니다.

예를 들어 canonical cut이 영화 PTS 120.00초에 있다면, 환자 7의 cleaned watchlog에서 pts=120.00에 대응하는 행을 찾고, 그 행의 neural_recording_time을 사용합니다. pause 때문에 동일 PTS 행이 반복될 때는 현재 pipeline이 사용하는 중복 행 선택 규칙을 따릅니다. 재생 중 건너뛴 frame이어서 해당 PTS가 없다면, timestamp를 꾸며내지 않고 skipped 등으로 남깁니다. 같은 컷을 다시 재생했다면 playback_occurrence를 구분해야 합니다.

우리 P001 경로는 실제로 공통 movie → subject별 cleaned-watchlog mapping을 독립 검사해 PASS_WITH_LIMITATIONS를 받았습니다. 하지만 이것은 저자가 사용한 raw-watchlog + upstream aligned-label 경로와 동일하다는 검증은 아닙니다. 이 불일치 가능성이 바로 P006을 수행한 이유입니다.

왜 굳이 두 경로를 비교하나? 두 경로가 서로 다른 timestamp를 낼 수 있다면, 동일 컷을 기준으로 계산한 post-event spike count가 달라질 수 있기 때문입니다. 이런 차이가 실제로 있는지는 같은 event임이 증명된 뒤에 계산해야 합니다.

3A. 세 가지 숫자가 서로 다르다는 것을 표로 이해하기

아래 표는 구조를 보여 주기 위한 가상의 한 환자 예시입니다. 숫자는 실제 NWB의 측정값이 아닙니다.

원천어떤 질문의 답인가?예시 값과 단위
annotations_base.start_time영화 자체에서 컷은 언제 생기는가?120.00초 (movie PTS)
cleaned_watchlogs환자의 이 movie frame은 neural recording 어느 시각에 해당하는가?pts=120.00초 → neural_recording_time=135,000 ms (예시)
annotations_patient_aligned.start_time원본 연구자의 환자별 정렬 방식은 이 컷을 neural recording 언제로 놓았는가?135,040 ms (예시)

우리 P001 onset이 135.000초, original onset이 135.040초라면 정말 같은 컷을 가리킬 때에만 Δt = −0.040초가 됩니다. 그러나 원본 row가 실제로 다른 재생 회차 또는 바로 이웃한 다른 frame을 가리킨다면 두 숫자의 차이는 유효한 오차가 아닙니다. 현재 P006은 이 identity를 아직 증명하지 못했습니다.

특히 P006 A2가 찾은 약 −40ms는 위 예시처럼 검증된 neural onset Δt가 아닙니다. 환자의 onset에서 찾은 가까운 watchlog movie PTS와 P001 쪽의 가까운 후보 movie PTS의 차이입니다. 이것이 frame convention 때문인지, 혹은 다른 이유 때문인지는 열려 있습니다.

4. v004가 한 것과 하지 못한 것

수행한 확인

  • 1,091 source annotation row의 canonical 후보 coverage
  • 29 subjects에서 `annotations_base` source 일관성
  • 32,234 patient rows의 k−1/k/k+1 watchlog locator evidence 보존
  • 출처가 없는 nearest-only identity를 승인하지 않음

아직 필요한 확인

  • Original `aligned_labels.npy`를 만든 upstream identity/frame convention 증거
  • 원본 patient entry와 canonical event의 검증된 유일한 대응
  • 동일 event의 neural onset Δt 분포 및 subject/segment별 drift
  • 필요하다면 영상 실제 frame-edge의 독립 확인
v004 수치 해석 주의: 보고서의 “source-supported proposals: 0”을 “해당 event correspondence가 물리적으로 없다”라고 읽으면 안 됩니다. 실제 pipeline은 선택적인 `objective_identity_evidence`를 공급하지 않은 채 nearest candidate 증거를 생성했습니다. 결과는 객관적인 identity proof를 획득하지 못했다는 것입니다.

5. 그래서 질문하신 '원본 경로를 정확히 재현할 수 없는가?'에 대한 답

부분적으로 맞습니다. 연구자의 최종 annotations_patient_aligned는 공개 NWB에 들어 있어 그 timestamp를 그대로 읽어 분석하는 것은 가능합니다. 또 저자의 NWB writer가 중간 결과를 불러와 최종 table로 쓰는 단계는 공개되어 있습니다.

하지만 aligned_labels.npy를 사전에 만드는 upstream 코드·그 입력 자료·결정 규칙이 공개된 범위에서 충분히 확보되지 않았으므로, 원본 raw playback에서 동일 intermediate와 동일 patient-aligned timestamps까지 완전 재생성하는 작업에는 아직 중요한 공백이 있습니다. 따라서 "원본 timing을 사용할 수 없다"도 틀리고, "그 생성 경로가 완전히 재현 가능하다"도 틀립니다.

현재 원본–P001 비교가 막힌 것은 두 개념을 동시에 명확히 하지 못했기 때문입니다. 첫째 동일한 canonical frame/event를 가리키는지의 identity proof, 둘째 그 환자의 playback 발생 회차에서 적용된 timestamp 변환 규칙입니다. 이 두 조건이 확인되어야 signed onset residual을 의미 있게 계산할 수 있습니다.
