06 · P006 Phase A · timing / identity audit

Original SUMMER의 event time과
우리 P001 event time은 어떻게 만들어지는가?

P006의 핵심 결과는 “두 timing이 몇 ms 다르다”가 아닙니다. 아직 같은 physical event를 양쪽에서 안정적으로 identify하지 못했기 때문에 timing residual을 계산할 수 없었다는 것입니다. 이 장에서는 original Figure 7 path, 우리 canonical/watchlog path, 그리고 P006이 두 path를 어떻게 연결하려 했는지를 분리해 이해합니다.

가장 중요한 결론: 현재 disposition은 UNRESOLVED_ALIGNMENT_IDENTITY이지 TIMING_MISMATCH가 아닙니다. 0 unique pairs라는 사실만으로 “우리 timestamp가 틀렸다”고 결론낼 수 없습니다.

1. 먼저 세 개의 clock을 구분하자

Movie clock

영화 내부 시간. 예: movie PTS = 1234.56 s. 25 fps라서 nominal frame interval은 40 ms입니다.

Presentation/laptop clock

실제 실험 laptop에서 해당 frame이 display된 wall-clock time입니다. pause가 발생하면 movie clock은 멈추지만 laptop clock은 계속 갑니다.

Neural recording clock

NeuraLynx acquisition system의 시간축. Spike times와 event times가 최종적으로 비교되는 좌표입니다.

movie PTS
   │  frame displayed
   ▼
presentation laptop time
   │  TTL pulses every ~1 s establish synchronization
   ▼
neural recording time
   │
   └── spikes live on this clock

Original paper에서는 presentation laptop의 frame log와 acquisition computer의 TTL arrival timestamps를 이용해 두 clock 사이의 linear transformation을 만들었다고 설명합니다. 보고된 평균 transformation error는 2.30 ms였습니다.

Original analysis의 핵심: Figure 7 code는 Camera Cut timing을 analysis 시점에 cleaned_watchlogs에서 다시 계산하지 않습니다. 각 subject NWB의 annotations_patient_aligned.start_time을 그대로 onset으로 사용합니다.
# official responsive-unit logic, conceptually
starts = annotations_patient_aligned["start_time"]
starts = starts[value == 1]

onsets = valid starts after same-label isolation
zetatest(spike_times / 1000, onsets / 1000, 1 sec)

또한 official NWB-generation code는 aligned_labels.npy를 읽어 annotations_patient_aligned를 만듭니다. 중요한 제한점은 이 aligned_labels.npy 자체를 생성한 upstream alignment code가 public repository에 포함되어 있지 않다는 점입니다. 따라서 patient-aligned timestamp가 raw watchlog와 TTL transform을 거쳐 정확히 어떤 세부 규칙으로 만들어졌는지 public code만으로 완전히 재구성할 수 없습니다.

Scientific Data paper는 annotations_patient_aligned가 각 patient의 raw watchlog에 추가로 aligned되어 pause와 playback alteration을 직접 반영한다고 설명합니다.

우리 pipeline은 subject-local patient-aligned row identity를 사용하지 않습니다. 대신 common-movie event를 먼저 안정적으로 정의한 뒤, 각 subject의 cleaned_watchlogs에서 해당 movie PTS를 찾습니다.

canonical event movie_time_sec
      ↓
find matching cleaned_watchlog.pts
      ↓

    choose the SECOND match
      ↓
cleaned_watchlog.neural_recording_time / 1000
      ↓

Rewind나 forward jump는 explicit playback segment boundary로 나누며, 해당 movie PTS가 없는 event는 skipped 또는 out_of_coverage로 남깁니다. 이 path는 annotations_patient_aligned.entry_index나 row order를 identity로 쓰지 않습니다.

5. P006 Phase A가 실제로 무엇을 했나?

P006은 original patient-aligned timing과 P001 timing을 바로 빼지 않았습니다. 먼저 동일한 event identity를 찾으려고 다음 reverse crosswalk을 시도했습니다.

annotations_patient_aligned.start_time
        │
        │ nearest neural timestamp within 20 ms
        ▼
cleaned_watchlog row
        │
        ├─ inferred movie PTS
        └─ inferred playback segment
        │
        ▼
search P001 occurrence with:
same subject
same event type
same playback segment
movie PTS within ±20 ms
        │
        ▼
ONLY if exactly one candidate:
compute residual = P001_time - patient_aligned_time
즉 nearest cleaned-watchlog row는 identity 자체가 아니라 evidence locator일 뿐입니다. P006은 그것만으로 같은 event라고 선언하지 않도록 일부러 fail-closed하게 설계되었습니다.

8. 가장 가능성 높은 discrepancy 원인들

High priority

A. Raw vs cleaned watchlog path

Original patient-aligned annotations는 raw playback history를 반영한다고 문서화되어 있지만, P001은 cleaned watchlog의 exact PTS lookup으로 neural time을 만듭니다. 같은 synchronization family라도 pause/seek 주변에서는 동일한 mapping이라고 가정할 수 없습니다.

High priority

B. Missing upstream aligned-label generator

Public repo는 aligned_labels.npy를 load하지만 그것을 어떻게 생성했는지 보여주지 않습니다. 따라서 event splitting, interpolation, duplicate handling, frame-edge convention을 완전히 audit할 수 없습니다.

High priority

C. Identity semantics differ

Patient-aligned entry_index는 alignment 이후 다시 생성됩니다. Row order와 entry index는 base-event identity가 아닙니다. P006의 0 unique pairs는 바로 이 identity gap을 드러냅니다.

Plausible

D. 20/40-ms frame convention shift

Frame start vs frame center, 0-based vs 1-based frame, “first frame of new segment”의 해석 차이는 20–40 ms systematic offset을 만들 수 있습니다. 현재 ±20 ms matching이면 한 frame(40 ms) shift만 있어도 전부 unmatched가 될 수 있습니다.

Plausible

E. Pause/replay row duplication or splitting

Patient-aligned positive row count가 canonical×subject보다 많다는 점과 잘 맞습니다. 같은 canonical transition이 alignment 과정에서 여러 aligned intervals로 표현될 가능성을 확인해야 합니다.

Separate issue

F. Isolation rules differ

Original Figure 7은 같은 label의 이전 positive interval과 1초 이상 떨어진 onset을 사용합니다. 우리 primary isolation은 모든 distinct physical transition에 대해 two-sided 1 s isolation을 사용합니다. 이는 event subset을 바꾸지만, 기본 timestamp 생성 차이와는 별 문제입니다.

9. 무엇은 오히려 가능성이 낮아 보이나?

Gross unit/clock catastrophe는 현재 evidence와 잘 맞지 않습니다. 32,234 patient rows 중 31,578은 patient-aligned neural onset에서 20 ms 이내에 unique cleaned-watchlog neural timestamp가 있습니다. 즉 seconds-vs-milliseconds 같은 대규모 unit error나 수초 수준의 global clock shift가 모든 row에 존재하는 그림은 아닙니다.

하지만 “neural time이 가까운 watchlog row가 존재한다”와 “그 row가 동일한 canonical cut의 movie frame이다”는 다른 주장입니다. 현재 문제는 후자입니다.

10. 다음에 가장 먼저 해야 할 diagnostic

Test 1 — movie-time offset histogram, identity claim 없이

각 patient-aligned row에서 nearest cleaned-watchlog row로 얻은 movie PTS와, 같은 event type의 nearest canonical event movie time 차이를 계산합니다. ±20 ms에서 match를 강제하지 말고 ±200 ms 정도를 diagnostic only로 보고 40 ms multiples에 peak가 있는지 확인합니다.

Δmovie = inferred_movie_pts_from_patient_time
       − nearest_same_type_canonical_event_time

Look for peaks at:
0 ms, ±20 ms, ±40 ms, ±80 ms, ...

Test 2 — subject/type count reconciliation

각 subject에서 Camera/Scene patient-aligned positive rows와 canonical occurrences 수를 비교하고, excess/deficit이 pause, jump, segment boundary 근처에 집중되는지 봅니다.

Test 3 — raw-watchlog reconstruction

가능하면 public raw_watchlogs와 base annotations로 patient-aligned onset을 독립 재구성합니다. Public generator가 없기 때문에 exact reproduction이 어려울 수 있지만, raw-vs-clean timing divergence가 어디서 생기는지 확인하는 가장 직접적인 방법입니다.

Test 4 — frame convention sweep

canonical event time을 −40, −20, 0, +20, +40 ms shifting한 diagnostic crosswalk을 만들어 candidate count가 급증하는지 봅니다. 이 결과는 timestamp를 수정하기 위한 것이 아니라 off-by-one / frame-edge hypothesis를 진단하기 위한 것입니다.

11. 그 다음에야 timing residual을 계산할 수 있다

Step A
Establish SAME EVENT identity
        ↓
Step B
Compare timestamps for that same event
        ↓
Δt = P001 neural time − original patient-aligned neural time
        ↓
Step C
Look at median / MAD / drift / tails
        ↓
Step D
Only then test whether neural conclusions change
현재는 Step A에서 멈춰 있습니다. 따라서 지금 P001 timestamps를 shift하거나 event를 drop하면 안 됩니다.

12. Original replication과 우리 analysis를 함께 보려면

Original-positive-control path

annotations_patient_aligned timestamps를 그대로 사용하여 Figure 7/ZETA를 method-compatible하게 reproduce합니다. 이것은 original timing representation이 public NWB에서 작동한다는 positive control입니다.

Canonical research path

Stable canonical event → cleaned watchlog → P001 timing을 사용합니다. 이 path는 sensory/structural/context predictors와 stable event identity를 연결하기 위해 설계되었습니다.

두 path가 같은 responsive-unit count를 대략 reproduce하면서도 event-by-event time이 완전히 동일하지 않을 수 있습니다. 반대로 둘이 systematic 40 ms shift를 갖더라도 1 s ZETA response count는 크게 달라지지 않을 수 있습니다. 그래서 population-level replication과 event-level identity/timing equivalence는 별도 검증이어야 합니다.

13. 기억할 핵심 5문장

  1. Original Figure 7은 annotations_patient_aligned.start_time을 직접 사용한다.
  2. 우리 P001은 canonical movie event를 cleaned_watchlogs에 다시 매핑해서 neural time을 만든다.
  3. 따라서 두 timing path는 related하지만 동일하지 않다.
  4. P006의 0 unique pairs는 timing residual이 0이 아니라, residual을 계산할 identity가 0개라는 뜻이다.
  5. 다음 우선순위는 timestamp를 수정하는 것이 아니라 identity gap과 possible 20/40-ms frame convention 차이를 진단하는 것이다.
