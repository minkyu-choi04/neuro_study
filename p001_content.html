P001 · Visual neuroscience study guide

영화의 한 순간과 한 neuron을
어떻게 “한 row”로 바꾸는가

SUMMER P001을 이해하기 위한 시각 교재입니다. 핵심은 raw spike timestamps → event alignment → windowed counts → unit × occurrence row입니다.

가장 중요한 한 문장: “900 occurrences가 neuron 안에 생긴다”가 아닙니다. 한 subject가 900개의 영화 transition을 보았고, 그 subject에게서 기록된 각 neuron에 대해 그 900개 transition 각각 주변의 spike를 측정하므로 100 neurons × 900 occurrences = 90,000 observations(rows)가 됩니다.

0. 전체 지도

Movie timeline
   ↓ transition annotations (Camera Cut / Scene Cut)
Canonical event
   ↓ subject별 실제 playback mapping
Subject-specific occurrence
   ↓ neural recording time으로 변환
Event time t = 0
   ↓ 같은 subject의 각 recorded neuron에서 spike timestamps를 정렬
Peri-event spike train
   ↓ baseline/post window 안의 spike를 count
One unit × occurrence row
   ↓ millions of rows
P001 table
   ↓
P002/P003/... Negative Binomial models

1. 가장 헷갈리는 부분: 100 neurons × 900 occurrences = 90,000 rows

가상의 Subject A가 영화를 보면서 900개의 usable transition occurrences를 경험했다고 합시다. 그리고 Subject A에게서 동시에/세션상 100개의 neural units가 기록되어 있다고 합시다.

영화 쪽

900 occurrences

Occ #1, #2, #3, …, #900

각 occurrence는 “이 subject가 실제로 경험한 한 transition instance”입니다.

뇌 쪽

100 neurons / units

Unit #1, #2, #3, …, #100

각 unit은 자신만의 spike train을 가집니다.

그러면 질문은 이렇게 바뀝니다.

각 transition occurrence 때, 각 neuron은 어떻게 반응했는가?
100 neurons × 900 occurrences = 90,000 neuron–event observations

위의 작은 칸 하나가 row 하나입니다. 세로축은 neuron, 가로축은 occurrence입니다. 실제 P001은 이 matrix를 long-format table로 펴놓은 것과 비슷합니다.

그렇다면 row 안에는 무엇이 들어가나?

개념적으로 row 하나는 아래와 같습니다. 실제 컬럼명은 구현에 따라 더 많지만, 의미는 이런 구조입니다.

“각 neuron에 900 occurrences가 있다”는 말은 틀렸나?

정확히 말하면 occurrence는 영화/subject 쪽 사건이고 neuron의 속성이 아닙니다. 하지만 분석에서는 그 same 900 occurrences에 대해 neuron #1의 response도 재고, neuron #2의 response도 재고, … neuron #100의 response도 잽니다.

Occurrence #17 (Scene Cut at subject neural time 1324.82s)
   ├── Unit 1 response  → one row
   ├── Unit 2 response  → one row
   ├── Unit 3 response  → one row
   └── ... Unit 100     → one row

Occurrence #18
   ├── Unit 1 response  → one row
   ├── Unit 2 response  → one row
   └── ...
따라서 occurrence가 neuron에 “속하는” 것이 아니라, 하나의 occurrence를 같은 subject의 여러 neurons에 대해 반복 관측하는 것입니다.

“그 occurrence를 실제로 경험한 subject의 neurons만 연결”의 의미

Subject A의 event occurrence를 Subject B의 neuron과 조합하면 안 됩니다. 둘은 서로 다른 사람의 뇌이기 때문입니다.

Correct:
Subject A occurrence #17  × Subject A unit #1
Subject A occurrence #17  × Subject A unit #2
...

Wrong:
Subject A occurrence #17  × Subject B unit #1   ✗

그래서 전체 row 수는 단순한 전체 units × 전체 occurrences가 아니라 subject별로 계산해서 더합니다.

Nrows = Σsubject s Nunits,s × Noccurrences,s

2. Neuron → spike → spike train

Neuron / unit

전극 신호에서 spike sorting으로 분리된 firing source입니다. SU(single unit)는 한 neuron에 더 가까운 분리, MU(multi unit)는 여러 neuron 신호가 섞였을 가능성이 큰 cluster입니다.

Spike

action potential의 발생 시점입니다. 분석 데이터에서는 흔히 [12.31, 12.88, 14.02, ...]처럼 timestamp 목록으로 표현됩니다.

Spike train

한 unit의 전체 spike timestamp sequence입니다. continuous waveform 그 자체가 아니라, event-time들의 열로 다루는 경우가 많습니다.

3. Canonical event, occurrence, movie time, neural time

Canonical event

영화 자체의 공통 timeline에서 정의된 transition입니다. 예를 들어 “canonical movie frame X에서 Scene Cut” 같은 식입니다.

Occurrence

그 canonical event가 특정 subject의 실제 playback에서 나타난 instance입니다. subject가 skip/replay/pause를 할 수 있기 때문에 canonical movie time과 neural recording time은 항상 같지 않습니다.

Canonical movie:
E17 -------- E18 -------- E19 -------- E20
10.0s        20.0s        30.0s        40.0s

Subject A playback/neural clock:
E17 -------- E18 -------------------- E20
112.4s       123.2s                  148.8s
              (E19 skipped)

Subject B playback/neural clock:
E17 ---- E18 ---- E18(replay) ---- E19 ---- E20
85.1s    94.9s    103.7s          114.0s   124.3s

따라서 event identity와 subject-specific occurrence는 다른 개념입니다.

4. Peri-event alignment: event를 t=0으로 맞추기

각 occurrence의 neural-time은 다르지만, 분석할 때는 그 occurrence를 기준으로 시간을 다시 정의합니다.

transition t=0
baseline
post
-1.0
-0.2
0
+1.0

예: event가 neural time 100.00 s이고 spike가 100.37 s에 있었다면 relative time은 +0.37 s입니다. spike가 99.65 s면 −0.35 s입니다.

relative spike time = spike time − event time

5. [-1.0,-0.2) 와 [0.0,1.0) 는 무엇인가?

Baseline [-1.0,-0.2)

transition 1초 전부터 0.2초 전까지입니다. 길이는 0.8초입니다.

event 직전 200 ms를 비워 두어 pre-transition activity와 baseline을 분리할 여지를 둡니다.

Post [0.0,1.0)

transition 순간부터 1초 직전까지입니다. 이 구간의 spike count가 rapid event response의 핵심 outcome이 됩니다.

[a,b)는 a를 포함하고 b는 제외하는 half-open interval입니다. 인접 window 경계의 spike를 두 번 세지 않게 해 줍니다.

예를 들어 relative spikes가 [-0.91,-0.72,-0.35,0.12,0.17,0.81,1.34]라면 baseline count=3, post count=3입니다.

6. Count, Raster, PSTH — 같은 spike data를 보는 세 가지 방법

① Count

정해진 window 안에 spike가 몇 개 있었는지만 셉니다.

[0,1): 6 spikes

P001 → NB model로 가기 가장 직접적인 표현

② Raster

여러 occurrence 각각에서 spike가 언제 발생했는지 시간 위치를 그대로 보존합니다.

trial/event별 temporal pattern, latency, consistency를 눈으로 확인하기 좋음

③ PSTH

여러 raster rows를 작은 time bin으로 나눠 평균해, event 전후 평균 firing profile을 만듭니다.

Population 또는 neuron의 평균 response shape를 보기 좋음

Raster를 어떻게 읽나?

가로축은 transition 기준 relative time, 세로축은 occurrence입니다. vertical tick 하나가 spike 하나입니다. 모든 occurrence에서 t≈0.2 s 근처에 spike가 몰리면 event-locked response가 있다는 힌트입니다.

PSTH를 어떻게 만드나?

1) 모든 occurrence를 t=0에 정렬
2) time axis를 작은 bins (예: 100 ms)로 나눔
3) 각 bin의 spike 수를 occurrence들에 걸쳐 합산/평균
4) bin width로 나누면 Hz 단위의 평균 firing rate
Count와 PSTH는 목적이 다릅니다. Count는 “0–1 s 동안 총 반응량”을 compact한 숫자로 만들어 regression에 쓰기 좋습니다. PSTH는 그 1초 안에서 response가 100 ms에 왔는지 700 ms에 왔는지 보여 줍니다.

7. Camera Cut vs Scene Cut

Camera Cut

편집상 shot/camera가 바뀌는 물리적 transition. 같은 장소와 같은 narrative event 안에서도 발생할 수 있습니다.

Scene Cut

더 큰 structural/narrative transition annotation. 장소·시간·상황 변화와 연관될 수 있습니다.

동일한 physical time point가 Camera Cut이면서 Scene Cut으로 annotation될 수 있으므로 annotation row 수와 distinct physical transition time 수는 같지 않을 수 있습니다.

8. Event isolation: 왜 가까운 transition을 제외하나?

Cut A                     Cut B
  |-------------------------|
  0 s                      +0.4 s

Cut A의 [0,1s) response를 세면 Cut B 이후 spike도 섞임 → 누구의 효과인지 모호

그래서 primary analysis에서는 일정 시간 범위 내 다른 physical transition이 없는 event를 사용해 contamination을 줄입니다.

9. Window completeness와 recording edge

event가 recording 시작 직후라면 baseline 전체를 볼 수 없습니다. 이런 row는 특정 window 분석에 사용할 수 없습니다.

recording starts
|
|    event
|      ↓
|------0-------------------------
     원하는 baseline [-1,-0.2) 일부가 recording 밖 → incomplete

10. 245만 rows가 245만 independent samples는 아니다

rows는 강한 hierarchy를 가집니다.

Subject
 ├─ Unit 1
 │   ├─ Occurrence 1
 │   ├─ Occurrence 2
 │   └─ ...
 ├─ Unit 2
 │   ├─ Occurrence 1
 │   └─ ...
 └─ ...

같은 neuron의 여러 rows는 같은 neuron에서 나온 반복 측정이고, 같은 subject의 여러 neurons도 같은 사람에 속합니다. 따라서 단순히 2.45M iid samples로 취급하면 안 됩니다.

11. P001을 이해하기 위한 전체 32개 개념

아래는 처음에 제시했던 학습 항목을 모두 넣은 요약판입니다. 앞부분에서 이미 자세히 설명한 것은 링크로 되돌아갈 수 있습니다.

  1. Neuron / Unit — extracellular recording에서 spike sorting으로 얻어진 firing source.
  2. Spike — neuron의 action potential 발생을 timestamp로 표현한 discrete event.
  3. Spike train — 한 unit의 spike timestamps 전체 sequence.
  4. Spike count vs firing rate — count는 window 내 개수, rate는 보통 count / window duration (Hz).
  5. Canonical event — subject와 독립적인 영화 timeline상의 transition identity.
  6. Camera Cut vs Scene Cut — 물리적 shot transition과 더 큰 structural transition의 구분.
  7. Annotation row vs physical transition — 동일 시간에 여러 labels가 있어 row 수와 distinct transition 수가 달라질 수 있음.
  8. Event isolation — 인접 transition이 response window를 오염시키지 않도록 exclusion.
  9. Movie time vs neural time — canonical film clock과 subject recording clock의 구분.
  10. Playback occurrence — canonical event가 특정 subject의 실제 playback에서 나타난 instance.
  11. Watchlog — skip/replay/pause 등을 반영해 movie time을 subject playback/neural time으로 매핑하는 기록.
  12. Unit × occurrence row — 특정 neuron이 특정 event occurrence 때 어떻게 반응했는지를 나타내는 한 observation.
  13. Peri-event alignment — 각 event를 t=0에 맞추는 과정.
  14. Relative spike time — spike_time − event_time.
  15. Baseline [-1,-0.2) — event 전 reference activity를 재는 primary window.
  16. 왜 [-1,0)이 아닌가 — immediate pre-event activity/ramping과 baseline을 분리할 수 있게 margin을 둠.
  17. Post [0,1) — rapid post-transition spike count를 재는 primary response window.
  18. Half-open interval [a,b) — 왼쪽 경계 포함, 오른쪽 제외.
  19. Sensitivity windows — primary window 선택에 결론이 과도하게 의존하는지 확인하는 대안 windows.
  20. Windowed spike count — raw timestamps를 regression용 discrete count로 요약.
  21. 왜 count를 보존하나 — spikes는 discrete events이며 Poisson/NB 계열 count model과 자연스럽게 연결.
  22. Raster — occurrence별 spike timing을 보존하는 시각화.
  23. PSTH — aligned raster를 time bins로 평균해 response time-course를 보여주는 histogram/rate curve.
  24. Hierarchical / nested structure — occurrences within units, units within subjects.
  25. SU-only primary population — cleaner single-unit interpretation을 위해 primary analysis에서 SU를 우선할 수 있음.
  26. Recording edge / complete window — 요구 window 전체가 실제 recording 범위 안에 있어야 함.
  27. Missingness — row는 존재해도 특정 window가 incomplete하거나 QC fail일 수 있음.
  28. Primary-isolation subset — 전체 rows 중 strict event-isolation 조건을 통과한 분석 subset.
  29. Baseline as covariate vs subtraction — post−baseline 한 값으로 단순화하지 않고 baseline을 predictor로 넣어 baseline state를 조절할 수 있음.
  30. Poisson vs Negative Binomial — NB는 spike count의 overdispersion(variance > mean)을 더 유연하게 허용.
  31. Nonstationarity — 긴 movie 동안 firing baseline이 천천히 변해 context 효과처럼 보일 위험.
  32. Event response vs context modulation — 궁극적 질문은 transition마다 같은 neuron의 response가 왜 다른지, sensory/structure/context가 그 차이를 설명하는지.

12. P001이 이후 model로 어떻게 이어지는가

Raw spikes
  ↓

  ├─ baseline spike count
  ├─ post spike count  ← model outcome
  ├─ subject/unit/event identity
  ├─ timing/QC/isolation
  └─ features joined later
        ↓
M0 nuisance
        ↓ + sensory
M1
        ↓ + current structural event
M2
        ↓ + preceding context
M3
        ↓ Event × Context test
M4

Baseline subtraction보다 covariate가 왜 유용한가?

post - baseline 하나만 만들면 count data의 구조를 바꾸고 baseline과 post 사이 관계를 강제로 계수 1로 가정하는 셈이 됩니다. 대신 post count를 outcome으로 두고 baseline count를 predictor로 넣으면 model이 baseline-response 관계를 데이터에서 추정할 수 있습니다.

Poisson vs Negative Binomial

Poisson은 평균과 분산이 비슷하다는 강한 가정을 갖습니다. 실제 neuron spike counts는 event 간 variability가 더 커서 overdispersion이 자주 나타납니다. NB는 extra dispersion parameter를 통해 이를 허용합니다.

Nonstationarity

83분 영화 동안 electrode/unit의 baseline firing이 천천히 올라가거나 내려갈 수 있습니다. context variable도 movie time과 연관될 수 있기 때문에 이 drift를 nuisance로 조절하지 않으면 false context effect가 생길 수 있습니다.

13. 이해 점검

Q1. Subject A가 80 units, 700 usable occurrences를 가지고 있다면 기본 unit×occurrence rows는 몇 개인가?
정답 보기

56,000 rows. 각 occurrence마다 그 subject의 80 units의 response를 각각 측정하기 때문입니다.

Q2. Occurrence #17은 neuron #5의 property인가?
정답 보기

아닙니다. occurrence는 subject가 경험한 movie event instance입니다. neuron #5와 occurrence #17을 조합하여 response observation 하나를 만듭니다.

Q3. Raster와 count의 가장 큰 차이는?
정답 보기

Count는 window 안의 총 spike 수만 남기므로 timing을 버립니다. Raster는 각 spike의 relative timing을 보존합니다.

Q4. PSTH는 무엇을 추가로 보여주나?
정답 보기

많은 aligned occurrences를 time bins로 평균해 평균 firing response의 시간적 shape와 latency를 보여줍니다.
